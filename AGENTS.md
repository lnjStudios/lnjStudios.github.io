# lnjhome: lnjstudios.com

Home site of Links & Joints Studios (one-person robotics studio sharing what it takes to build robots, YouTube DIY/tinkerer image). Hugo extended
+ `themes/hugo-brewm` (git submodule of `foxihd/hugo-brewm`). Plain `hugo`: no Node, no extra build steps or scripts.

## Run / build

```sh
git submodule update --init --recursive
hugo server                     # dev (config/development/hugo.toml: drafts, future posts, no git info); search works
hugo --gc --minify --cleanDestinationDir   # production
hugo server --bind 0.0.0.0 --baseURL / --appendPort=false   # dev, also reachable from a phone: http://<laptop-ip>:1313
```

For the phone, use a relative baseURL, not `--baseURL http://<ip>:1313/`: brewm loads its CSS/JS from absolute
URLs (`.Permalink`), so any host mismatch leaves the page unstyled with no gear and no tools. Share links and the QR
are relative in that mode (Copy link still copies the full address).

Hugo is the snap (0.168.0), meant to be held (`sudo snap refresh --hold hugo`); keep `HUGO_VERSION` in
`.github/workflows/hugo.yml` equal to `hugo version`. Update the theme with
`git submodule update --remote --merge themes/hugo-brewm`.

## Deploy

Push to `main` → `.github/workflows/hugo.yml` → GitHub Pages. baseURL comes from `hugo.toml`
(`https://lnjstudios.com/`), not from Pages, so canonical/og/sitemap URLs stay https.
`lnjstudios.com/ros-man` is a **Cloudflare redirect rule** (302 to ROS-Manager's raw script on GitHub), not a
Hugo page; never add a `/ros-man` page or path, and don't break that redirect.

## Layout

- `hugo.toml`: site config, brewm params (logo, accent colours, fonts, search), menus (`main`, `more`, `footer` icons).
- `content/` root holds only `_index.md` (home greeter; `trailer: true` puts the animated channel trailer in the
  16:9 hero slot, see below; its `cover`, a hotlinked brewm flowline placeholder, is now only the share image)
  and folders; every page gets its own folder (`about/index.md`, `write/index.md`).
  Don't put loose `.md` files there. Headless things use Hugo's `build` options (`render: never`), not brewm's
  `params.headless` / `target`, which publish a redirect page per file.
- `content/essentials/`: site building blocks, no page or URL of their own (cascaded `build: render: never`):
  `footer.md` (the footer card: body = blurb, `links` = pills; copyright + social icons come from `hugo.toml`
  `params.copyright` / `menus.footer`) and `404.md` (the 404 page's text, `buttons`, the robot's `log` line).
  - Footer: `layouts/partials/main/footer.html` overrides brewm's (which made a column per `type: footer` page);
    one tinted card on every page, `custom.css` "Footer". It's `partialCached`: nothing page-specific in it.
    It must stay clear of the floating rail: above 640px both sides leave the rail's lane (`--lnj-rail-lane`), so
    it stays centred; on phones it's full width and its bottom margin clears the rail stack (`--lnj-rail-n`
    pills, counted with `:has`; update the counts if the rail gains or loses a button). Its bottom margin clears
    the gear + search row, except on desktop home, where the footer is in the right pane only (the dock is under
    the left one): there its bottom edge sits on the dock's line (`--lnj-dock-bottom`), level with the dock pills.
  - 404: `layouts/404.html` (uses our baseof; GitHub Pages serves `/404.html` for any missing address; the rail
    skips Share there). "4 0 4" with the LnJ mark as the 0, its two paths read at build time from
    `static/images/brand/lnj-studios-ink.svg` (the first two `<path>`s); one endless 8 s CSS loop (the joint
    works loose, leaps behind the right 4, peeks, leaps home with a click, the mark hops, then the 4s; the lidar
    scan and the joint's floor shadow show only while it's away), `custom.css` "404 page", still with reduced
    motion. Everything keeps time with the 8 s loop (the sweep is 2 s). Each moving part is in a group translated
    to its pivot, so keyframes turn about 0 0; the joint is nested x / y / squash / spin groups (`jx jy js jr`) so
    a leap is a real arc (x linear, y ease-out quad up and ease-in quad down, spin linear). Keep keyframes at
    turning points only, or the motion stops and starts.
- `content/slides/*.md`: home carousel, any number of slides (`type: slide`, ordered by `weight`; `_index.md`
  cascades `build: {render: never, list: always}` so they're headless but still in `site.RegularPages`).
  `newsletter.md` (`/newsletter/`) and `parts.md` (`/parts/`) are the pages slide buttons open; they live here
  with a `url:` and `build: {render: always}` to opt back in.
  Front matter: `cover`, `alt`, and `buttons: [{label, url}]` (0..n). Covers are transparent PNGs cropped tight to
  the shape (shown with `object-fit: contain`), generated by `uv run scripts/slide_art.py`; edit the script and
  re-run rather than hand-editing the PNGs. A real photo works too.
  Rendered by our own `layouts/partials/carousel.html` (overrides brewm's) + `assets/js/lnj-slides.js`:
  autoplay (`data-interval` in the partial, 6 s), pauses on hover/keyboard focus, slides move sideways,
  drag/swipe/horizontal wheel/arrow keys to change. Styles in `assets/css/custom.css`.
- **Authors** (taxonomy `author`, front matter `author: [koustav]`): each author's page is
  `content/author/<id>/_index.md` (`layout: resume`, `url: /<id>/`, `avatar` for bylines, `photo` for the page).
  brewm's cards link the name to it; our byline and "About this post" take the name / avatar / link from it, and
  the page lists the author's posts ("Writing"). Posts without an author page use `byline: {name, avatar}`.
- `content/about/index.md` (`layout: about` → `layouts/_default/about.html`) and `content/author/koustav/_index.md` (`layout:
  resume` → `layouts/_default/resume.html`, `/koustav/`): their own layouts, not the article one, driven by front
  matter (about: `headline`, `subtitle`, `explore` cards, `person` (photo / name / role come from the résumé page;
  `title` "At the bench" and a one-line `bio`), `write`; résumé: `photo` (cut-out PNG, used as is, never cropped),
  `role`, `tagline`, `contact` (first = filled button; `partials/contact-buttons.html`), `core` (primary skills,
  big chips), `experience` (`note`, `points`), `projects`, `side` (side projects: a site `page` or title/url/text;
  only the big ones, e.g. ROS-Manager), `skills`, `education`, `achievements`). The résumé is Koustav's hiring
  portfolio and follows his PDF CV; only real facts; no city on the site (the phone number is public only as the WhatsApp button, his choice). Empty lists drop
  their section. It prints as a clean CV ("Save as PDF"). Styles: `custom.css` "About /
  résumé pages". `content/write/index.md` (`/write/`): the step-by-step guide for authors (GitHub web editor, front
  matter, Markdown, pictures, code); keep it in step with the archetype and front matter fields.
- `.github/ISSUE_TEMPLATE/guide-request.yml`: the "Request a guide" form (only works once pushed).
- `content/tools/<slug>/index.md`: products/tools (`type: post`, category Tools). `content/notes/<slug>/index.md`:
  short posts (category Notes), often pointing into docs.lnjstudios.com.
- Home on mobile / tablet (≤1152px, one column), keep it: logo, slider, photo + greeter text, categories, recent
  posts, Discover topics (flex `order` in `custom.css`; brewm's own order differs). On phones (≤640px) every other
  page gets a 1.25rem text gutter (logo row included; brewm's phone gutter is `--vfoot`, which we zeroed) and no
  breadcrumbs. On those non-home pages
  (≤1152px) all floating buttons hide while scrolling down and come back on a small scroll up (`lnj-rail.js`,
  `body.lnj-chrome-hidden`); never while Settings is open or search has focus.
- Home pane layout (desktop), keep it: left column = title card (logo) over the slides pane; right = categories
  on top, then the photo + recent posts, with the greeter text + Discover topics in a narrow column beside them.
- **Home trailer** (`layouts/partials/home-trailer.html`, called from our `partials/hero.html` override of brewm's inline
  hero when the page has `trailer: true`; styles `custom.css` "Home trailer"): a 30 s looping "channel trailer": 01 Build (the
  About AMR drops together, powers up, drives off), 02 Code (a terminal types `colcon build` + a Nav2 launch), 03 Grab
  (a 3-joint arm with a gripper picks a cube off the floor onto a stand; IK poses in the keyframes), 04 Drive
  (top-down map, the plan draws, the robot follows it), 05 Share (a video of the robot plays; Videos / Tools / Docs),
  then the end card (the LnJ mark snaps together as on the 404, name, `@linksnjoints`). Chapters start at
  0 / 4.75 / 9.5 / 14.25 / 19 / 23.75 s; each sets `--d`, parts add `--o`, so keyframes are in chapter time (1 % = 0.3 s);
  offset parts reset 20 s into their loop (while off screen). CSS only except the robot's path in 04 (SMIL
  `animateMotion`, keyTimes in loop fractions); the inline script re-syncs it to the CSS clock and pauses it all
  off screen, in a hidden tab or with the small pause button (bottom right). Base styles = the end card (what reduced motion shows).
  The greeter text beside it is one block centred on its height (h1 then paragraphs, no stretched gap).
- No top or bottom bar, not even their space: `--vhead` / `--vfoot` are forced to 0 in `custom.css`. The header
  is just the logo. Desktop home: the whole left column (title card + slides pane) is `position: fixed`; only the
  right side scrolls. The logo is the "title card", sized and centred on the category cards' row
  (brewm cards are 12.8rem), and the slides pane starts below that row (`--lnj-pane-top`). If brewm's card size
  changes, update those two places in `custom.css`. Elsewhere `--lnj-logo-h` is 3.5rem.
- Wheel over the slides pane changes slides and never scrolls the page; dots are vertical on the pane's right edge
  above the buttons (desktop), horizontal at the top on phones.
- **Bottom dock.** Left: brewm's footer row (`#body-footer`) holding only the Settings gear + search pill
  (brewm's own back-to-top `nav` is hidden). Right: our vertical **rail**. All are pills on one baseline
  (`--lnj-dock-*`); icon-only pills (`.lnj-pill`, and the gear) slide a label (`.lnj-pill__label`) out on
  hover / keyboard focus, to the left on the rail. No `title` tooltips.
- `layouts/partials/analytics.html` is brewm's end-of-body hook (`params.analytics.append = 'body'`, no analytics).
  brewm calls it with `partialCached` (no key), so it renders **once per site**: nothing page-specific in it.
  - **Search** pill (`assets/js/lnj-search.js`), moved after the gear by an inline script: Hugo renders the
    index itself from `assets/json/search-index.json` (`type: post` pages only, like Hextra's
    `search-data.json`); the JS fetches it and matches every typed word (title > tags > description > body).
    Results open upward, `/` focuses. brewm's own search (DuckDuckGo / Pagefind) is off
    (`params.search.enable = false`). Don't add Pagefind or other build steps back.
  - **Settings** (`assets/js/lnj-settings.js`): brewm's Accessibility panel behind the gear; saves on every
    change (same localStorage keys as brewm's Save); bottom row is About us (filled accent pill, `lnj-btn--accent`, so it stands out) + animated RSS icon. It
    also moves brewm's BionRead toggle off the bar into the panel as a switch, shown on posts only (BionRead only
    works on brewm's single layout); every other page gets home's Settings (Reading mode + Dyslexic). brewm's focus mode
    (⦿) is hidden in CSS.
- `layouts/_default/baseof.html`: copy of brewm's with two added partials: `head/image-alt.html` (og/twitter
  image alt, which brewm lacks) and `rail.html` (per page). The rail must stay **after** the footer: brewm's CSS
  uses `main#page + footer` (BionRead, baseline stretch). Re-copy it if brewm's baseof changes.
- `layouts/partials/rail.html` + `assets/js/lnj-rail.js`: the right-hand rail, top to bottom: back-to-top (only
  once scrolled past half a screen), then on home **Links & Docs** (LD mark `static/images/brand/links-and-docs.png`,
  cropped from the docs repo's `lnj_dark-mode.png`, CSS mask), elsewhere **Categories** (a pill per category, with
  its count), **Share** (not on the 404; page QR from Hugo's `images.QR` into `images/qr/`, LinkedIn / X / Reddit / WhatsApp from
  brewm's icon font, Copy link / Copy QR) and **Home**. Categories / Share are drawers (button + `.lnj-drawer`,
  not `<details>`, so the height can animate): the toggle stays put, floating pills slide open right above it
  (grid rows `0fr` → `1fr`, pushing only the buttons above it up), and its icon spins into an ×. One open at a time.
- Settings switches (`input.toggle + label`: Reading mode = brewm's `#optimizeSR`, OpenDyslexic, BionRead) are
  accent pills with a status dot, not brewm's track + knob, grouped by `lnj-settings.js` into one row
  (`.lnj-a11y-switches`). Labels are shortened in `i18n/en.toml` (site overrides of brewm's strings). On article
  pages Reading mode is hidden there (it's in the page tools) and BionRead appears; elsewhere it's Reading mode + Dyslexic.
  "Article pages" here and below means posts (`type: post`, `main#page.post`), not About / `/write/` / etc.
- `layouts/partials/page-tools.html` + `assets/js/lnj-tools.js` (posts only, called from `rail.html`; other pages
  have no page tools at all, their Reading mode is in Settings): fixed
  stack just right of the article column, top (top right up to 1152px): **Contents** (only if the page has h2/h3;

  clicked again, highlights the current section), **Reading mode** (brewm's "screen reader optimisation", a
  plainer page, no audio, so never call it "screen reader"; clicks brewm's hidden `#useSR`, so brewm applies and
  saves it), **Print**. Replaces brewm's `#menu`. On every screen it slides up and away while scrolling down
  and comes back on a small scroll up (`body.lnj-chrome-hidden`, `lnj-rail.js`); on wide screens it's the only

- Article header: brewm's inline partials can be overridden by same-name files in `layouts/partials/`.

  `params.author` in `hugo.toml`; avatar a link, fetched + resized at build via `resources.GetRemote`, or a site
  path under `assets/` (resized) or `static/` (as is); the name links to About | date) followed by the tags as small accent

## Content rules

- Real things only: no invented team, clients, numbers or testimonials. Artphilic no longer exists; don't link it.
- Brand is location-neutral (international): don't mention Mumbai or any city.
- Tone: helpful and humble, shares freely; nothing salesy. Don't repeat the same info more than twice on the site.
- Posts need `type: post`, a `description`, a category (`Tools` or `Notes`), tags, a `stage` and an `author` (or a `byline`);
  `level`, `license`, `links`, `disclaimer` are optional (shown in About this post, not in the body);
  `archetypes/default.md` has the template (`hugo new notes/<slug>/index.md`). Don't put a map in `author`: brewm
  prints `author` as a plain name (cards, RSS, meta). Add `lastmod: YYYY-MM-DD` when a post is meaningfully edited.
- Polygon Editor's sample maps (`factory_*`) may come from work; ask before publishing or naming them.

## Gotchas

- brewm's inline "graceful degradation" CSS caps every `img` at `86vw` even when its stylesheet loads; `custom.css`
  overrides it (`max-width: 100%`), else phone images stop short of the text's right edge. On phones, list cards
  drop brewm's side padding (text + image on the page gutter) and the home greeter spans the photo's width.
- `cover` is the feed card / social preview image (2:1); the article header shows `banner` (a wide image made for the
  page) or, without one, `cover`. Don't also put that image at the top of the body.
- Slide covers are cropped to a tall box; use portrait art, not wide banners.
- `public/` and `resources/_gen/` are build output and ignored; never commit them.
